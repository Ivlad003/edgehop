# edgehop

Одна миша й одна клавіатура на кілька комп'ютерів. Доводиш курсор до краю
екрана — він переходить на сусідній комп'ютер, і клавіатура разом з ним.
Як Logitech Flow, тільки з **будь-якою** мишею та клавіатурою (Bluetooth, USB,
вбудований тачпад) і для **Windows, macOS та Linux**.

Миша й клавіатура підключені до одного комп'ютера (це *сервер*). Решта
комп'ютерів — *клієнти*: вони отримують рухи й натискання мережею і відтворюють
їх у себе. Клієнтів може бути скільки завгодно.

```
   ┌─────────┐      ┌───────────────┐      ┌─────────┐
   │ laptop  │ ◄──► │     desk      │ ◄──► │ macbook │
   │ (Linux) │      │ (Windows)     │      │ (macOS) │
   └─────────┘      │ миша + клав.  │      └─────────┘
     клієнт         └───────────────┘        клієнт
                         сервер
```

## Стан

| Платформа | Сервер (до нього підключена миша) | Клієнт |
|-----------|-----------------------------------|--------|
| Windows 10/11 | перевірено на реальній машині | перевірено на реальній машині |
| macOS | зібрано, **на реальному Mac ще не запускалось** | зібрано, **ще не запускалось** |
| Linux (Ubuntu, X11 і Wayland) | зібрано, **ще не запускалось**, експериментально | зібрано, **ще не запускалось** |

Що саме перевірено:

- мережеве ядро (протокол, шифрування, перемикання між 2–3 екранами,
  пропуск вимкнених комп'ютерів, перепідключення) — автотестами; поки що вони
  запускались лише на Windows (CI в `.github/workflows` проганяє їх на всіх
  трьох ОС після публікації на GitHub);
- Windows — `edgehop selftest --grab` на живій системі: захоплення миші та
  клавіатури, приховування курсора, 124 клавіші, 5 кнопок, колесо і точність
  позиціювання до пікселя;
- macOS і Linux — тільки компіляція. Код написаний за документацією до API,
  але перший запуск на цих системах може виявити помилки.

## Швидкий старт

Потрібен один файл `edgehop` (або `edgehop.exe`) на кожному комп'ютері —
зібрати його можна командою нижче в розділі «Збірка».

**1. На комп'ютері з мишею й клавіатурою** — назвіть усі екрани зліва направо
так, як вони стоять на столі:

```
edgehop init server --name desk --row "laptop,desk,macbook"
```

Команда створить конфіг і надрукує готовий рядок для інших комп'ютерів (з
адресою та ключем).

**2. На кожному іншому комп'ютері** — виконайте надрукований рядок, підставивши
його ім'я з `--row`:

```
edgehop init client --server 192.168.1.10 --key <ключ> --name macbook
```

**3. Запустіть `edgehop` на всіх комп'ютерах** (порядок не важливий — клієнти
самі чекають на сервер і перепідключаються).

Тепер ведіть курсор за правий край `desk` — він з'явиться на `macbook`.
**Ctrl+Alt+Shift+Backspace** будь-коли повертає курсор на сервер.

Корисні команди: `edgehop info` (екрани, адреси, де лежить конфіг),
`edgehop -v` (докладний журнал), `edgehop help`.

## Дозволи та мережа

**Мережа.** Сервер слухає порт `24920` (TCP і UDP). Відкрити його треба тільки
на сервері; клієнти самі починають з'єднання. Windows при першому запуску
сервера спитає про брандмауер — дозвольте для приватних мереж.

**Windows.** Нічого встановлювати не треба. Щоб edgehop працював і тоді, коли
активне вікно запущене від адміністратора (диспетчер завдань, інсталятори),
запускайте його теж від адміністратора.

**macOS.** У *System Settings → Privacy & Security* увімкніть програму, з якої
запускаєте edgehop (Terminal, iTerm …), у розділах **Accessibility** та
**Input Monitoring**. Якщо файл завантажено з інтернету:

```
chmod +x edgehop && xattr -d com.apple.quarantine edgehop
```

**Linux.** Потрібен доступ до `/dev/uinput` та `/dev/input/event*`. Або
запускайте через `sudo`, або один раз дайте доступ своєму користувачу:

```
sudo usermod -aG input $USER
echo 'KERNEL=="uinput", GROUP="input", MODE="0660", OPTIONS+="static_node=uinput"' | sudo tee /etc/udev/rules.d/60-edgehop.rules
sudo udevadm control --reload-rules && sudo udevadm trigger
```

і перезайдіть у систему. Якщо розмір екрана визначився неправильно, вкажіть
його в конфігу: `screen_size = "2560x1440"`.

## Конфіг

Файл `edgehop.toml` шукається так: прапорець `-c ФАЙЛ`, змінна
`EDGEHOP_CONFIG`, `./edgehop.toml`, далі тека користувача:

- Windows: `%AppData%\edgehop\edgehop.toml`
- macOS: `~/Library/Application Support/edgehop/edgehop.toml`
- Linux: `~/.config/edgehop/edgehop.toml`

Сервер:

```toml
role = "server"
name = "desk"
key  = "…"                       # однаковий на всіх комп'ютерах
listen = "0.0.0.0:24920"

row = ["laptop", "desk", "macbook"]   # екрани зліва направо

# Екрани зверху/знизу додаються зв'язками:
[[links]]
from = "desk"
side = "top"                     # left, right, top, bottom
to   = "tv"

release_hotkey = "ctrl+alt+shift+backspace"   # "none" — вимкнути
hide_cursor = true               # ховати курсор сервера, поки він керує іншим

[screens.macbook]
scale = 1.0                             # швидкість курсора на цьому екрані
remap = { alt = "meta", meta = "alt" }  # напр. PC-клавіатура керує Mac
```

Клієнт:

```toml
role = "client"
name = "macbook"
key  = "…"
server = "192.168.1.10"          # адреса сервера, порт необов'язковий
```

Додаткові параметри: `screen_size = "1920x1080"` (якщо розмір визначено
неправильно), `pointer_speed` та `pointer_accel` (тільки для Linux-сервера).

Клавіші передаються як *фізичні* клавіші, тому розкладку (мову) перемикає сам
комп'ютер, на якому зараз курсор, — так само, як із власною клавіатурою.

## Чому не гальмує

- Рух курсора йде по **UDP** абсолютними координатами: загублений пакет нічого
  не псує, бо наступний (через кілька мілісекунд) несе актуальну позицію. TCP
  на Wi-Fi у такій ситуації «завмирає» на сотні мілісекунд.
- Клавіші, кліки й колесо йдуть по TCP (вони не повинні губитися), з вимкненим
  алгоритмом Нейгла. Клік несе позицію курсора, тож завжди влучає туди, де
  курсор був на сервері.
- Якщо UDP заблоковано, рух автоматично йде по TCP; остання позиція завжди
  дублюється по TCP, тож курсор зупиняється точно там, де треба.
- Якщо події накопичились, рухи зливаються в один — черга застарілих позицій
  не утворюється.
- На сервері Windows беруться вже прискорені системою переміщення, тому курсор
  на іншому комп'ютері відчувається так само, як локальний.

Виміряна затримка обробки (від перехоплення на сервері до руху курсора на
клієнті, обидва процеси на одній Windows-машині, тобто без самої мережі):
менше 1 мс (`go test -run TestMotionLatency -v ./internal/server/`).

## Безпека

Мережею передається все, що ви друкуєте, зокрема паролі, тому з'єднання завжди
шифрується. Обидві сторони мають спільний `key`; з нього та з одноразових
ключів X25519 виводяться сеансові ключі AES-256-GCM. Комп'ютер без правильного
ключа або з іменем, якого немає в розкладці сервера, не підключиться. Конфіг
містить ключ — не публікуйте його (він уже в `.gitignore`).

## Обмеження

- Ctrl+Alt+Del та Win+L завжди спрацьовують на сервері — Windows не дає їх
  перехопити.
- Екран блокування, UAC-запити й вікна адміністратора на Windows недоступні,
  якщо edgehop запущено не від адміністратора.
- Буфер обміну між комп'ютерами поки не синхронізується.
- Курсор на клієнті ставиться абсолютними координатами, тому ігри, які
  захоплюють мишу (шутери), на клієнті не працюватимуть.
- Перехід відбувається одразу при дотику до краю (затримки чи «подвійного
  дотику» поки немає). Під час перетягування із затиснутою кнопкою курсор
  екран не покидає.
- Linux-сервер сам рухає курсор, тому його швидкість задається в конфігу
  edgehop, а не в налаштуваннях системи; тачпад ноутбука не передається.
- На Linux з кількома моніторами розмір робочого столу може знадобитися
  вказати вручну.
- На macOS Caps Lock і медіаклавіші можуть не спрацьовувати.

## Плани

- перевірка та доведення macOS і Linux на реальних машинах;
- спільний буфер обміну;
- затримка/модифікатор для переходу через край, перемикання гарячими клавішами;
- автозапуск (служба Windows, launchd, systemd) та значок у треї;
- автоматичний пошук сервера в локальній мережі.

## Збірка

Потрібен Go 1.21 або новіший. Залежностей із C немає, тож усе збирається з
будь-якої системи під будь-яку:

```
go build -o edgehop ./cmd/edgehop          # для поточної системи
./build.sh        # або .\build.ps1 — усі платформи в теку dist/
go test ./...
```

Структура:

| Тека | Що там |
|------|--------|
| `cmd/edgehop` | командний рядок |
| `internal/server` | сервер: хто зараз володіє курсором, пересилання вводу |
| `internal/client` | клієнт: з'єднання із сервером, відтворення вводу |
| `internal/input` | робота з ОС: `windows.go`, `darwin.go`, `linux.go` |
| `internal/secure` | рукостискання та шифрований канал (TCP + UDP) |
| `internal/proto` | формат повідомлень |
| `internal/layout` | розташування екранів, краї, точки входу |
| `internal/keys` | коди клавіш і таблиці для кожної ОС |
| `internal/config` | файл `edgehop.toml` |

Діагностика на Windows: `edgehop selftest` перевіряє встановлення перехоплювачів,
`edgehop selftest --grab` приблизно на пів секунди забирає мишу й клавіатуру та
проганяє через Windows усі клавіші, кнопки й колесо.
