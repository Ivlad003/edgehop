# edgehop

Одна миша й одна клавіатура на кілька комп'ютерів. Доводиш курсор до краю
екрана — він переходить на сусідній комп'ютер, і клавіатура разом з ним.
Як Logitech Flow, тільки з **будь-якою** мишею та клавіатурою (Bluetooth, USB,
вбудований тачпад) і для **Windows, macOS та Linux**.

**Сайт і завантаження: <https://ivlad003.github.io/edgehop/>**

Миша й клавіатура підключені до одного комп'ютера (це *сервер*). Решта
комп'ютерів — *клієнти*: вони отримують рухи й натискання мережею і відтворюють
їх у себе. Клієнтів може бути скільки завгодно.

```
   ┌─────────┐      ┌───────────────┐      ┌─────────┐
   │ laptop  │ ◄──► │     desk      │ ◄──► │ macbook │
   │ (Linux) │      │ (Windows)     │      │ (macOS) │
   └─────────┘      │ миша + клав.  │      └─────────┘
     клієнт         └───────────────┘        клієнт
                         сервер
```

## Стан

| Платформа | Перехоплення й відтворення вводу | Як перевірено |
|-----------|----------------------------------|---------------|
| Windows 10/11 | працює | самотест на реальній машині: `edgehop selftest --grab` |
| macOS (Apple Silicon) | працює | живий тест на справжньому Mac у CI |
| Linux | працює на рівні ядра | живий тест у CI через uinput/evdev; **на справжньому робочому столі (GNOME, Wayland чи X11) ще не запускалось** |

**Чого ще ніхто не робив: повний сценарій на двох окремих комп'ютерах.** Усі
перевірки нижче — на одній машині.

Що саме перевірено:

- мережеве ядро (протокол, шифрування, перемикання між 2–3 екранами,
  пропуск вимкнених комп'ютерів, перепідключення) — автотестами на Windows,
  macOS і Linux на кожен коміт;
- клавіші переходу на екран і захист від випадкового переходу (затримка,
  клавіші, кути) — автотестами сервера: стрибок із сервера й між двома
  клієнтами, повернення на те саме місце, вимкнений комп'ютер, перетягування,
  відлік затримки з власним годинником. Як перехоплення розпізнає самі клавіші
  на кожній системі — у живих тестах нижче. Не перевірено: справжні миша й
  клавіатура на двох окремих комп'ютерах;
- Windows — `edgehop selftest --grab` на живій системі: захоплення миші та
  клавіатури, приховування курсора, 124 клавіші, 5 кнопок, колесо і точність
  позиціювання до пікселя. Живий тест там само: гаряча клавіша ловиться і
  коли курсор на сервері, і коли на іншому комп'ютері, її остання клавіша до
  Windows не доходить; подія краю несе затиснуті модифікатори й відстань до
  кута; після повернення курсор стає туди, звідки його забрала клавіша;
- macOS — живий тест у CI на справжньому Mac: синтетичний ввід справді рухає
  курсор у точну позицію; перехоплення бачить край екрана (і які модифікатори
  при цьому затиснуто), ловить гарячі клавіші в обох режимах, у режимі
  керування іншим комп'ютером поглинає й передає рух, 91 клавішу, кнопки та
  колесо, а після повернення курсор стає в точку входу. Не перевірено: рух справжньої
  миші (тест подає події програмно), приховування курсора на вигляд, кілька
  дисплеїв;
- Linux — живий тест у CI проти справжнього ядра: віртуальні пристрої
  віддають рівно ті події, які просили (103 клавіші, рух, кнопки, колесо), а
  перехоплення забирає «фізичні» пристрої, пропускає ввід локально, бачить
  край екрана (з модифікаторами й відстанню до кута), ловить гарячі клавіші в
  обох режимах і не пропускає їхню останню клавішу далі, поглинає й передає
  ввід у режимі керування іншим комп'ютером.
  Не перевірено: як робочий стіл показує курсор від віртуального пристрою,
  кілька моніторів, визначення розміру екрана;
- сторінка налаштувань — автотестами (доступ, збереження, запуск і зупинка) та
  вручну в браузері на Windows: сервер і клієнт на одній машині, підключення
  видно на сторінці;
- спільний буфер обміну — логіка передачі автотестами (текст і файли в обидва
  боки, пересилання між двома клієнтами, обмеження розміру, ворожі шляхи);
  системний буфер обміну — живим тестом у CI на справжніх Windows, macOS і
  Linux (текст і списки файлів записуються й читаються). Не перевірено:
  вставлення отриманих файлів у Провідник і Finder та передача між двома
  окремими комп'ютерами;
- надсилання файлів зі сторінки — автотестами (приймання файлів сторінкою,
  ворожі шляхи, доставка в теку отримувача) та вручну в браузері на Windows:
  сервер і два клієнти на одній машині, файли й теки в обидва боки, зокрема
  6 МБ з побайтовим порівнянням, скасування й відмова, коли отримувача немає.
  Не перевірено: між двома окремими комп'ютерами, справжнє перетягування теки
  мишею (тест подавав файли програмно), браузери, крім Chromium;
- інсталятори й готові збірки — CI ставить останній реліз обома скриптами на
  Windows, macOS і Linux і запускає програму.

Живі тести можна запустити й у себе: `EDGEHOP_LIVE=1 go test ./internal/input/
-run Live -v` (на Linux — від root; тест рухає курсор і на мить забирає ввід).

## Швидкий старт

Потрібен один файл `edgehop` (або `edgehop.exe`) на кожному комп'ютері.
Найшвидше поставити його з термінала.

macOS і Linux:

```
curl -fsSL https://raw.githubusercontent.com/Ivlad003/edgehop/main/install.sh | sh
```

Windows (PowerShell):

```
irm https://raw.githubusercontent.com/Ivlad003/edgehop/main/install.ps1 | iex
```

Скрипт завантажує останній реліз саме для вашого комп'ютера, перевіряє
контрольну суму SHA-256 і кладе програму в теку користувача (`~/.local/bin`
або `%LOCALAPPDATA%\Programs\edgehop`), права адміністратора не потрібні. На
Windows він також додає цю теку до PATH користувача. Конкретну версію можна
задати змінною `EDGEHOP_VERSION=v0.1.0`, іншу теку — `EDGEHOP_INSTALL_DIR`.

Готові файли для Windows (x64, ARM64), macOS (Apple Silicon, Intel) і Linux
(x64, ARM64) лежать на [сторінці релізів](https://github.com/Ivlad003/edgehop/releases/latest);
зібрати самому — розділ «Збірка».

**1. Запустіть `edgehop` на кожному комп'ютері.** У браузері відкриється
сторінка налаштувань.

**2. На комп'ютері з мишею й клавіатурою** оберіть «Миша й клавіатура
підключені сюди», розставте екрани зліва направо так, як вони стоять на столі,
і натисніть «Зберегти і запустити». Сторінка покаже адресу та ключ для інших
комп'ютерів.

**3. На кожному іншому комп'ютері** оберіть «Цим комп'ютером керують з іншого»,
введіть адресу й ключ із першого комп'ютера та ім'я, під яким цей екран
записано в розкладці.

Тепер ведіть курсор за край екрана — він з'явиться на сусідньому комп'ютері.
**Ctrl+Alt+Shift+Backspace** будь-коли повертає курсор на сервер. Порядок
запуску не важливий: клієнти самі чекають на сервер і перепідключаються.

Якщо курсор тікає на сусідній комп'ютер, коли ви цього не хотіли, увімкніть
на сервері затримку на краю або перехід лише із затиснутою клавішею; а щоб
перескакувати на потрібний комп'ютер із клавіатури, задайте йому клавіші
переходу. Усе це — у розділі «Конфіг» і на сторінці налаштувань.

### Сторінка налаштувань

- Відкривається лише з цього комп'ютера (`http://127.0.0.1:24921`) і лише за
  посиланням з кодом доступу, яке edgehop друкує під час запуску. Після першого
  відкриття браузер запам'ятовує доступ.
- Показує, які комп'ютери підключені, на якому з них зараз курсор, і журнал.
- Блок «Надіслати файли»: перетягніть на сторінку файли або теки — вони
  з'являться на іншому комп'ютері (докладніше — розділ «Надсилання файлів»).
- **Де який екран стоїть, задається на комп'ютері з мишею** (сервері): ряд
  «Екрани зліва направо» плюс необов'язкові екрани зверху і знизу. На
  керованих комп'ютерах цих налаштувань немає.
- Там само, на сервері, задаються клавіші переходу на кожен екран і захист від
  випадкового переходу через край (затримка, клавіші, кути) — докладніше в
  розділі «Конфіг».
- Коли інший комп'ютер з правильним ключем стукає, а в розкладці його ще
  немає, сервер показує його вгорі сторінки з кнопками «Додати ліворуч» і
  «Додати праворуч». Сторінка клієнта тим часом пояснює, чому він ще не
  підключений (не доданий на сервері, не той ключ, сервер не відповідає).
- Тримайте вікно edgehop відкритим: закриття вікна зупиняє спільне керування.
- Мова перемикається кнопкою вгорі (українська / англійська).

### Те саме з командного рядка

```
edgehop init server --name desk --row "laptop,desk,macbook"
edgehop init client --server 192.168.1.10 --key <ключ> --name macbook
edgehop run            # запуск без сторінки налаштувань; -v — докладний журнал
```

`edgehop init server` друкує готовий рядок для інших комп'ютерів. Корисні
команди: `edgehop info` (екрани, адреси, де лежить конфіг), `edgehop help`.

## Дозволи та мережа

**Мережа.** Сервер слухає порт `24920` (TCP і UDP). Відкрити його треба тільки
на сервері; клієнти самі починають з'єднання. Windows при першому запуску
сервера спитає про брандмауер — дозвольте для приватних мереж.

**Windows.** Нічого встановлювати не треба. Щоб edgehop працював і тоді, коли
активне вікно запущене від адміністратора (диспетчер завдань, інсталятори),
запускайте його теж від адміністратора.

**macOS.** У *System Settings → Privacy & Security* увімкніть програму, з якої
запускаєте edgehop (Terminal, iTerm …), у розділах **Accessibility** та
**Input Monitoring**. Якщо файл завантажено з інтернету:

```
chmod +x edgehop && xattr -d com.apple.quarantine edgehop
```

**Linux.** Потрібен доступ до `/dev/uinput` та `/dev/input/event*`. Або
запускайте через `sudo`, або один раз дайте доступ своєму користувачу:

```
sudo usermod -aG input $USER
echo 'KERNEL=="uinput", GROUP="input", MODE="0660", OPTIONS+="static_node=uinput"' | sudo tee /etc/udev/rules.d/60-edgehop.rules
sudo udevadm control --reload-rules && sudo udevadm trigger
```

і перезайдіть у систему. Якщо розмір екрана визначився неправильно, вкажіть
його в конфігу: `screen_size = "2560x1440"`.

## Конфіг

Файл `edgehop.toml` шукається так: прапорець `-c ФАЙЛ`, змінна
`EDGEHOP_CONFIG`, `./edgehop.toml`, далі тека користувача:

- Windows: `%AppData%\edgehop\edgehop.toml`
- macOS: `~/Library/Application Support/edgehop/edgehop.toml`
- Linux: `~/.config/edgehop/edgehop.toml`

Сервер:

```toml
role = "server"
name = "desk"
key  = "…"                       # однаковий на всіх комп'ютерах
listen = "0.0.0.0:24920"

row = ["laptop", "desk", "macbook"]   # екрани зліва направо

# Екрани зверху/знизу додаються зв'язками:
[[links]]
from = "desk"
side = "top"                     # left, right, top, bottom
to   = "tv"

release_hotkey = "ctrl+alt+shift+backspace"   # "none" — вимкнути
hide_cursor = true               # ховати курсор сервера, поки він керує іншим

# Захист від випадкового переходу через край (типово все вимкнено):
switch_delay_ms = 250            # стільки мілісекунд курсор має тиснути в край
switch_keys = "ctrl"             # перехід лише поки натиснуто ці клавіші
switch_corner = 40               # не переходити ближче ніж за 40 пікселів від кута

[screens.macbook]
scale = 1.0                             # швидкість курсора на цьому екрані
remap = { alt = "meta", meta = "alt" }  # напр. PC-клавіатура керує Mac
hotkey = "ctrl+alt+2"                   # перенести курсор на цей екран звідусіль
```

Клієнт:

```toml
role = "client"
name = "macbook"
key  = "…"
server = "192.168.1.10"          # адреса сервера, порт необов'язковий
```

Додаткові параметри: `screen_size = "1920x1080"` (якщо розмір визначено
неправильно), `pointer_speed` та `pointer_accel` (тільки для Linux-сервера),
`downloads = "…"` (тека для файлів, надісланих на цей комп'ютер; типово
`edgehop` у теці завантажень).

«Віддалені вікна» — експеримент версій 0.4–0.7 — прибрано у 0.8. Їхні
параметри `remote_windows` і `window_keys` у старих конфігах просто
ігноруються, а комп'ютери з 0.8 і старішими версіями й далі працюють разом.

Клавіші передаються як *фізичні* клавіші, тому розкладку (мову) перемикає сам
комп'ютер, на якому зараз курсор, — так само, як із власною клавіатурою.

### Клавіші переходу на екран

`hotkey` у розділі `[screens.ім'я]` переносить курсор разом із клавіатурою на
цей екран, хоч би де курсор був — на сервері чи на іншому комп'ютері. На
сторінці налаштувань це поле «Клавіші переходу» в «Параметрах екранів».
Типово клавіш немає. І клавіші переходу, і захист від випадкового переходу
(нижче) працюють на сервері, тож для них досить оновити до 0.9 комп'ютер із
мишею; керовані комп'ютери можуть лишатися на 0.8.

- Курсор з'являється там, де він був на тому екрані востаннє; першого разу —
  посередині.
- На сервер так само повертає `release_hotkey`. Якщо курсор забрала із сервера
  гаряча клавіша, він повертається на те саме місце.
- Комп'ютер не підключений — клавіші нічого не роблять. Під час перетягування
  (затиснута кнопка миші) теж.
- Комбінація — це модифікатори й одна звичайна клавіша наприкінці:
  `ctrl+alt+2`, `win+f1`, `ctrl+shift+m` або сама `f13`. `ctrl`, `alt`
  (`option`), `shift`, `win` (`cmd`) означають будь-яку з двох клавіш;
  `leftctrl`, `rightalt` — конкретну.
- Остання клавіша комбінації не друкується ніде. Ctrl, Alt та інші
  модифікатори комп'ютер, на якому був курсор, устигає побачити (натиснуто й
  відпущено, без літери).
- Комбінацію edgehop забирає собі на всіх комп'ютерах, тож обирайте таку, якою
  не користуються система й ваші програми. Однакові клавіші для двох екранів
  або такі самі, як `release_hotkey`, — помилка в конфігу. Зайві затиснуті
  модифікатори не заважають (`ctrl+2` спрацює і з Ctrl+Shift+2); якщо підходять
  дві комбінації, спрацьовує та, що вимагає більше клавіш.
- Модифікатор, який ви ще тримаєте після переходу, на новому екрані треба
  натиснути знову.

### Захист від випадкового переходу

Три параметри сервера, які можна поєднувати. На сторінці налаштувань — блок
«Захист від випадкового переходу». Діють на краях усіх екранів, і сервера, і
керованих комп'ютерів; задаються лише на сервері. Типово все вимкнено: курсор
переходить одразу, щойно торкнувся краю.

- `switch_delay_ms = 250` — курсор має тиснути в край стільки мілісекунд
  поспіль. Зупинили руку чи відвели курсор — відлік починається заново.
  Найбільше 5000.
- `switch_keys = "ctrl"` — курсор переходить, лише поки натиснуто ці клавіші:
  `ctrl`, `alt` (`option`), `shift`, `win` (`cmd`) або кілька через `+`.
  `"none"` чи порожньо — клавіші не потрібні.
- `switch_corner = 40` — ближче ніж за стільки пікселів від кута екрана курсор
  не переходить, тож гарячі кути macOS і кнопка «Пуск» лишаються досяжними.
  На короткій стороні кут ніколи не займає більше чверті. Найбільше 1000.
  На сервері з Windows чи macOS кути рахуються для кожного монітора окремо, на
  керованих комп'ютерах і на Linux-сервері — для всього робочого столу.

Якщо задано кілька параметрів, мають виконуватись усі: затримка рахується,
лише поки натиснуто клавіші й курсор не в куті. Клавіш переходу захист не
стосується — вони спрацьовують завжди.

## Спільний буфер обміну

Скопіюйте текст або файли на одному комп'ютері (Ctrl+C / Cmd+C), переведіть
курсор на інший і вставте (Ctrl+V / Cmd+V).

- **Текст** передається одразу, щойно курсор переходить на інший екран.
- **Файли й теки** копіюються так само: вміст передається на інший комп'ютер
  у службову теку, а в його буфер обміну потрапляє список цих файлів, тож їх
  можна вставити у Провідник, Finder чи інший файловий менеджер.
- Передається лише тоді, коли треба: вміст іде на той екран, куди перейшов
  курсор, якщо там його ще немає. Між двома керованими комп'ютерами він
  проходить через сервер.
- Великі файли не гальмують мишу й клавіатуру: вміст іде окремим
  зашифрованим з'єднанням.
- Обмеження розміру — 200 МБ (змінюється на сторінці налаштувань або
  `clipboard_max_mb` у конфігу). Вимкнути: `clipboard = false`.

Чого немає:

- Зображення в буфері (наприклад знімок екрана) поки не передаються.
- На Linux потрібен `xclip` (X11) або `wl-clipboard` (Wayland).

## Надсилання файлів

На сторінці налаштувань є блок «Надіслати файли». Перетягніть на сторінку
файли або теки (або натисніть «Вибрати файли» чи «Вибрати папку») — вони
з'являться на іншому комп'ютері.

- **Куди потрапляють.** У теку `edgehop` в завантаженнях отримувача
  (`~/Downloads/edgehop`); змінити — `downloads = "…"` у його конфігу. Сторінка
  показує цю теку. Якщо файл із таким іменем уже є, новий отримує назву
  `ім'я (2).txt` — нічого не перезаписується.
- **Кому.** Із сервера — будь-якому підключеному комп'ютеру (якщо їх кілька,
  отримувач обирається кнопкою). З керованого комп'ютера — серверу.
- Структура тек зберігається. Обмеження розміру немає: файли йдуть частинами
  окремим зашифрованим з'єднанням і не гальмують мишу й клавіатуру.
- Буфер обміну при цьому не зачіпається, тож це працює і з `clipboard = false`.
- Потрібен edgehop 0.3 або новіший на обох комп'ютерах.

Як це влаштовано: браузер ніколи не каже сторінці, де файл лежить на диску,
тому сторінка спершу передає його програмі edgehop на цьому ж комп'ютері
(тимчасова копія в системній теці тимчасових файлів, яку edgehop видаляє після
надсилання), а вже вона шле його далі.

Чого немає: **перетягування файлу мишею через край екрана** просто на робочий
стіл іншого комп'ютера. Для цього треба підробляти системне перетягування на
обох системах; Deskflow, найпопулярніший аналог, цю можливість прибрав.

## Чому не гальмує

- Рух курсора йде по **UDP** абсолютними координатами: загублений пакет нічого
  не псує, бо наступний (через кілька мілісекунд) несе актуальну позицію. TCP
  на Wi-Fi у такій ситуації «завмирає» на сотні мілісекунд.
- Клавіші, кліки й колесо йдуть по TCP (вони не повинні губитися), з вимкненим
  алгоритмом Нейгла. Клік несе позицію курсора, тож завжди влучає туди, де
  курсор був на сервері.
- Якщо UDP заблоковано, рух автоматично йде по TCP; остання позиція завжди
  дублюється по TCP, тож курсор зупиняється точно там, де треба.
- Якщо події накопичились, рухи зливаються в один — черга застарілих позицій
  не утворюється.
- На сервері Windows беруться вже прискорені системою переміщення, тому курсор
  на іншому комп'ютері відчувається так само, як локальний.

Виміряна затримка обробки (від перехоплення на сервері до руху курсора на
клієнті, обидва процеси на одній Windows-машині, тобто без самої мережі):
менше 1 мс (`go test -run TestMotionLatency -v ./internal/server/`).

## Безпека

Мережею передається все, що ви друкуєте, зокрема паролі, тому з'єднання завжди
шифрується. Обидві сторони мають спільний `key`; з нього та з одноразових
ключів X25519 виводяться сеансові ключі AES-256-GCM. Комп'ютер без правильного
ключа або з іменем, якого немає в розкладці сервера, не підключиться. Конфіг
містить ключ — не публікуйте його (він уже в `.gitignore`).

## Обмеження

- Ctrl+Alt+Del та Win+L завжди спрацьовують на сервері — Windows не дає їх
  перехопити.
- Екран блокування, UAC-запити й вікна адміністратора на Windows недоступні,
  якщо edgehop запущено не від адміністратора.
- Файл не можна перетягнути мишею через край екрана просто на інший
  комп'ютер — його перетягують на сторінку edgehop або копіюють і вставляють.
  Зображення в буфері обміну не передаються.
- Керований комп'ютер надсилає файли лише серверу, а не іншому керованому.
- Курсор на клієнті ставиться абсолютними координатами, тому ігри, які
  захоплюють мишу (шутери), на клієнті не працюватимуть.
- Типово перехід відбувається одразу при дотику до краю: затримку, клавіші чи
  захист кутів треба ввімкнути самому (розділ «Конфіг»). «Подвійного дотику»
  немає. Під час перетягування із затиснутою кнопкою курсор екран не покидає —
  ні через край, ні за клавішами переходу.
- На Windows-сервері після Ctrl+Alt+Del чи Win+L клавіші Ctrl, Alt або Win
  треба натиснути заново, щоб edgehop знову побачив їх затиснутими.
- Linux-сервер сам рухає курсор, тому його швидкість задається в конфігу
  edgehop, а не в налаштуваннях системи; тачпад ноутбука не передається.
- На Linux з кількома моніторами розмір робочого столу може знадобитися
  вказати вручну.
- На macOS Caps Lock і медіаклавіші можуть не спрацьовувати.

## Плани

- перевірка та доведення macOS і Linux на реальних машинах;
- зображення в спільному буфері обміну;
- автозапуск (служба Windows, launchd, systemd) та значок у треї замість
  вікна консолі;
- автоматичний пошук сервера в локальній мережі.

## Збірка

Потрібен Go 1.21 або новіший. Залежностей із C немає, тож усе збирається з
будь-якої системи під будь-яку:

```
go build -o edgehop ./cmd/edgehop          # для поточної системи
go install github.com/Ivlad003/edgehop/cmd/edgehop@latest   # або одразу з GitHub
./build.sh        # або .\build.ps1 — усі платформи в теку dist/
go test ./...
```

## Публікація

Усе потрібне для GitHub уже лежить у репозиторії:

- **Збірки.** `.github/workflows/ci.yml` на кожен коміт запускає тести на
  Windows, macOS і Linux та збирає всі платформи.
- **Версії.** `.github/workflows/release.yml` збирає й публікує реліз, щойно
  з'являється тег версії:

  ```
  git tag v0.1.0
  git push origin v0.1.0
  ```

- **Сайт.** `.github/workflows/pages.yml` викладає теку `site/` на GitHub Pages.
  Кнопки завантаження на сайті завжди ведуть на останній реліз. Один раз треба
  ввімкнути Pages: *Settings → Pages → Source: GitHub Actions*.

Структура:

| Тека | Що там |
|------|--------|
| `cmd/edgehop` | командний рядок |
| `internal/server` | сервер: хто зараз володіє курсором, пересилання вводу |
| `internal/client` | клієнт: з'єднання із сервером, відтворення вводу |
| `internal/ui` | локальна сторінка налаштувань (`web/` — сама сторінка) |
| `site` | сайт проєкту для GitHub Pages |
| `internal/input` | робота з ОС: `windows.go`, `darwin.go`, `linux.go` |
| `internal/secure` | рукостискання та шифрований канал (TCP + UDP) |
| `internal/proto` | формат повідомлень |
| `internal/layout` | розташування екранів, краї, точки входу |
| `internal/clip` | системний буфер обміну: `clip_windows.go`, `clip_darwin.go`, `clip_linux.go` |
| `internal/xfer` | передача тексту й файлів частинами, перевірка шляхів і розміру |
| `internal/keys` | коди клавіш і таблиці для кожної ОС |
| `internal/config` | файл `edgehop.toml` |

Діагностика на Windows: `edgehop selftest` перевіряє встановлення перехоплювачів,
`edgehop selftest --grab` приблизно на пів секунди забирає мишу й клавіатуру та
проганяє через Windows усі клавіші, кнопки й колесо.
